# Development Learning Log — Grocery Receipt Auditor

Personal learning record for the `bill_checker` project. Updated after every task.

## Project goal

Mobile-first web app that audits French supermarket receipts: compares what you
actually bought vs. what you were charged, and detects promotions that should
have been applied but weren't.

Core rule: **AI extracts data, deterministic Python decides.** An LLM never
decides whether money is owed — it only reads images/text. All financial
verdicts come from testable Python engines.

### Key concepts learned so far

- **Layered architecture**: routers (HTTP) → services (infra/AI) → engines
  (business rules) → models (DB). Dependencies point inward; engines never
  import FastAPI.
- **Models vs schemas**: SQLAlchemy models = DB shape; Pydantic schemas = API
  shape. Keeping them separate lets the DB change without breaking the API.
- **`JSONB().with_variant(JSON(), "sqlite")`**: portable column type — real
  JSONB in production Postgres, plain JSON in SQLite tests.
- **PBKDF2 over bcrypt**: stdlib-only password hashing (no native deps,
  works on Python 3.14), 600k iterations, per-user salt, constant-time compare.
- **JWT**: stateless auth token signed with `SECRET_KEY`; contains `sub`
  (user id) + expiry. Server verifies signature — no session table needed.
- **Storage abstraction**: files addressed by opaque keys, never public URLs —
  receipts are private data.

### Deep dive completed: Docker Compose

- Container = isolated process from an image; Compose = declarative
  orchestration of the whole stack.
- `ports: HOST:CONTAINER` — inside the network services use names (`db:5432`),
  from Windows you use `localhost:5432`. "localhost" = whoever asks.
- `POSTGRES_*` env vars initialize only on first boot (empty data dir).
- Named volumes persist data; `down` keeps them, `down -v` wipes the DB.
- `depends_on` alone ≠ ready — `condition: service_healthy` waits for the
  healthcheck (pg_isready / redis-cli ping / mc ready).
- `env_file` loads `.env`; `environment:` keys override it — compose pins
  container-network URLs that differ from host URLs.
- Bind mounts (`./backend:/app`) give live reload; dependencies are baked at
  image build → `docker compose build` after changing pyproject/package.json.
- `/app/node_modules` anonymous volume keeps Linux-built deps alive while the
  host folder is mounted over `/app`.
- MinIO = self-hosted S3: port 9000 API, 9001 console; DB stores keys, not blobs.

## Task 2 — First runnable API (done)

### Implemented

- `app/main.py` — FastAPI app object + CORS (frontend origin only) + mounts `/api/v1`
- `app/api/v1/health.py` — `GET /api/v1/health`
- `app/api/v1/auth.py` — `POST /register` (201 + JWT), `POST /login`, `GET /me` (JWT-protected)
- `app/api/v1/router.py` — aggregates feature routers onto one `api_router`
- `alembic.ini` + `alembic/env.py` + `script.py.mako` — migration tooling wired to app settings
- `alembic/versions/fc8d5d87d079_initial_schema.py` — first migration, all 16 tables
- `email-validator` added to deps (required by `EmailStr`)

### Concepts learned

- **APIRouter**: mini-app per feature; `prefix`/`tags` group endpoints in Swagger.
  `main.py` mounts them under `/api/v1` for versioning.
- **`response_model=`**: FastAPI serializes output through the schema — extra
  ORM fields can't leak into responses.
- **Dependency injection**: `Depends(get_db)` yields a session, auto-closed even
  on exceptions; `Depends(get_current_user)` turns routes protected in one line.
- **Alembic workflow**: `revision --autogenerate` diffs `Base.metadata` vs the
  real DB → writes a migration; `upgrade head` applies it. `alembic_version`
  table tracks applied revisions. Always READ autogenerated files before applying.
- **IntegrityError → 409**: duplicate email hits the DB unique constraint;
  app catches it, rolls back, returns clean 409.
- **Anti-enumeration**: login returns the same "Email ou mot de passe
  incorrect" whether email or password is wrong.
- **Debugging win**: port conflict — a native Windows Postgres service was
  already on 5432; connections hit the wrong DB. Fixed by remapping Docker's
  HOST port to 5433 (`netstat -ano` + `tasklist` to identify listeners).
  Lesson: container port ≠ host port; conflicts are host-side.

### Verified

- `alembic upgrade head` → 16 tables + `alembic_version` in Postgres
- register → 201 + JWT; login → JWT; /me + token → user; /me sans token → 401
  "Authentification requise"; wrong password → 401

### Commands reference

```bash
cd backend && python -m venv .venv
.venv/Scripts/pip install -e ".[dev]"
docker compose up -d db          # host port 5433 (5432 = local PG service)
.venv/Scripts/alembic upgrade head
.venv/Scripts/uvicorn app.main:app --reload
# Swagger UI: http://localhost:8000/docs
```

## Task 3 — Audit sessions & file upload (done)

### Implemented

- `app/api/v1/sessions.py` — create/list/detail sessions, basket-photo and
  receipt uploads
- `AuditSessionDetailOut` — nested response schema (items + receipts)
- Session status transitions: DRAFT → PRODUCTS_CAPTURED → RECEIPT_UPLOADED

### Concepts learned

- **UploadFile / multipart**: file uploads aren't JSON — browser sends
  `multipart/form-data`; FastAPI exposes `UploadFile` via `File(...)`.
- **Validation boundary**: content-type allowlist (415) + size cap (413)
  checked BEFORE touching storage — never trust `file.filename` or the
  declared type blindly.
- **Object keys**: `sessions/{sid}/basket/{uuid}.{ext}` — unguessable,
  organized by owner, opaque. DB stores the key, storage holds bytes.
- **Anti-enumeration (again)**: other user's session → 404 not 403 —
  don't reveal the resource exists.
- **N+1 problem**: loading `session.basket_items` lazily fires 1 query per
  item. `selectinload` fetches children in 2 queries total (IN-list join).
- **Windows gotcha**: Git Bash `/tmp` ≠ Windows curl path — native curl.exe
  needs `C:/...` in `-F "file=@..."`.

### Verified

- Upload PNG → `UploadResult` + file on disk under `data/uploads/sessions/...`
- Detail endpoint returns nested basket_items + receipts
- text/plain → 415; other user's session → 404

## Task 4 — Test harness (done)

### Implemented

- `tests/conftest.py` — SQLite-in-memory engine (StaticPool), tmp-dir
  storage, `dependency_overrides` for get_db/get_storage, `client` +
  `auth_headers` fixtures
- `tests/test_api.py` — 10 API contract tests: auth, sessions, upload
  validation, user isolation
- Refactored `sessions.py`: storage is now `Depends(get_storage)` so tests
  can override it (was a direct call — unswappable)
- Fixed dev SECRET_KEY length (HS256 needs ≥32 bytes) + asyncio pytest config

### Concepts learned

- **Arrange-Act-Assert**: fixture sets up → client.post() acts → assert
  checks status + JSON contract.
- **Fixtures = pytest's DI**: `def test_x(client, auth_headers)` — pytest
  injects by argument name; `yield` splits setup/teardown.
- **dependency_overrides**: `app.dependency_overrides[get_db] = fake` — the
  swap point. This is THE reason we inject rather than call directly.
- **StaticPool**: in-memory SQLite is per-connection — StaticPool shares one
  connection or tables vanish between queries.
- **TestClient**: runs the real ASGI app in-process — full stack test, zero
  network.
- **Test the contract**: status codes, isolation (404 across users), "hash
  never in response" — not internals.

### Verified

`pytest -q` → 10 passed in ~9s.

## Task 5 — Receipt OCR pipeline (done)

### Implemented

- `services/ocr/types.py` — `ReceiptExtraction`/`ReceiptLineExtraction`
  schemas + `OCRProvider` Protocol + `OCRProviderError`
- `services/ocr/groq_provider.py` — Groq vision, strict-JSON prompt
  (French, "n'invente rien"), temperature=0, Pydantic-validated output
- `services/ocr/fixture.py` — canned Carrefour receipt (OCR_BACKEND=fixture,
  dev without API key)
- `services/receipt_parse.py` — deterministic validator: per-line math
  (qty×unit≈total), sum(items)+sum(discounts)≈total ±0.02 → adjusts
  confidence, writes items/discounts, logs `receipt_parsed` AuditEvent
- `POST /sessions/{sid}/receipts/{rid}/parse` endpoint
- `Receipt.discounts`/`items` now `cascade="all, delete-orphan"`

### Concepts learned

- **AI extracts, Python verifies**: provider returns claims; deterministic
  arithmetic re-scores confidence. Model says 0.9, math says otherwise →
  math wins.
- **Protocol typing**: `OCRProvider` is a duck-typed interface — groq,
  fixture, future PaddleOCR all satisfy it without a common base class.
- **delete-orphan cascade** + assigning collections wholesale
  (`receipt.items = [...]`): keeps ORM identity-map state equal to DB —
  bypassing the collection (db.add with raw FK) caused a stale-empty
  response bug caught by tests.
- **Idempotent re-parse**: replacing the collection means re-running parse
  never duplicates rows.
- **temperature=0** for extraction tasks — we want determinism, not
  creativity; `response_format=json_object` forces parseable output.

### Verified

- 15/15 tests pass (5 new OCR tests: items+discounts created, incoherent
  total penalized, bad line math penalized, idempotent re-parse, 404s)
- Live: fixture backend → parse → real rows + AuditEvent, confidence 1.0
